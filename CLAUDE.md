# FORGE — Claude Code Context

## What This Is
FORGE (Factory for Orchestrated Runtime Generation of Engines) is a meta-system that generates full-stack apps from YAML specs. It produces 3 layers: Directive (config/prompts), Orchestration (n8n workflow JSON), and Execution (FastAPI backend + HTML templates).

## Key Files
- `forge.py` — The build engine. All generation logic lives here.
- `specs/coop-briefing.yaml` — The only app spec currently. Defines COOP Morning Briefing.
- `output/` — Generated output (gitignored, regenerated by `python3 forge.py build`).

## Build & Test
```bash
python3 forge.py build specs/coop-briefing.yaml   # Generate all 16 files
python3 forge.py validate specs/coop-briefing.yaml # Validate spec only
```

## Architecture Rules
- **output/ is ephemeral** — never hand-edit files there. Fix forge.py instead.
- **n8n connections use node names**, not IDs. Connection keys must match the `name` field on nodes.
- **Webhook nodes need `webhookId`** or n8n namespaces the path and it won't resolve at the short URL.
- **POST sources** (like planner) are called inline in the Code node after merge, not as separate HTTP request nodes. They need upstream data from GET sources.
- **GET sources** become HTTP Request nodes wired through merge.
- **Delivery nodes** reference `$json.subject`, `$json.body`, `$json.voice` — the Code node must produce all of these.

## API Response Shapes
- `/api/triage/inbox` — flat JSON array of `{id, thread_id, subject, sender, snippet, date, importance, reason, suggested_action}`
- `/api/calendar/events` — flat JSON array of `{id, summary, start, end, location, description, all_day}`
- `/api/planner/generate` — POST with `{date, calendar_events[], triaged_emails[]}`, returns `{date, blocks[], top_priorities[], email_actions[], summary}`
- `/api/gmail/send` — POST with `{to, subject, body}`
- `/api/voice/speak` — POST with `{text}`, returns mp3 stream
